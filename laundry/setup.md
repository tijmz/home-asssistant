# Introduction
If my laundry is done, I need to remove it from the machine. What I wanted is to have Home Assistant create a Todoist task if the laundry was done and send me an actionable notification on my phone. I should be able to complete and tick off the task via Todoist, but I also wanted to be able to do it straight from the Home Assistant notification. This proved somewhat difficult: there is a Todoist integration for Home Assistant, but it does not throw you the task id that you need to remove a specific, but newly generated task. I took a different approach, creating REST commands to converse with the Todoist API and using these REST commands in automations. And it worked.

# Preparation
You need a couple of things before you can also do this:

- Somehow, Home Assistant should know when your washer is done.
- You need a Todoist account and an API key for that account

# Setting up the automation

## Creating REST commands
First up, create REST commands in ```configuration.yaml``` in your Home Assistant installation. Add the following lines:

```yaml
rest_command:
  todoist_create_task:
    url: "https://api.todoist.com/rest/v2/tasks"
    method: POST
    headers:
      Authorization: "Bearer YOUR_API_KEY"
      Content-Type: "application/json"
    payload: '{"content": "{{ content }}", "description": "{{ description }}", "due_string": "{{ due_string }}", "priority": {{ priority | default(1) }}, {% if section_id is defined %}
        "section_id": "{{ section_id }}" {% endif %}}'
    
  todoist_close_task:
    url: "https://api.todoist.com/rest/v2/tasks/{{ task_id }}/close"
    method: POST
    headers:
      Authorization: "Bearer YOUR_API_KEY"
```

This gives you two new commands: one will generate tasks in Todoist, while accepting a number of parameters. The other allows you to close off a task based on a specific ``task_id``. It's worth mentioning that you can tweak the payload for ``todoist_create_task``, for example to include a project ID.

## Generating a task if laundry is done
You can do this many way. I wanted the task to have a description that generated by an LLM on the fly. You might not care for that. My setup is as follows:

```yaml
alias: Laundry completed alert
description: >-
  This automation generates a Todoist task if the laundry is done and sends
  actionable notification to phone.
triggers:
  - trigger: state
    entity_id:
      - sensor.wasmachine_job_state # This works well with the Samsung washer I happen to have. Others might signal this based on a power draw, or connected to a washer with a different state change.
    to:
      - finish
conditions: []
actions:
  - action: ai_task.generate_data
    metadata: {}
    data:
      task_name: Washer is done
      instructions: >-
        Provide a text which fits into a phone notification. Not multiple options, no use of Markdown, just the message. Make sure the message is funny and notifies the user that the washer is done and that laundry can be taken out. 
    response_variable: laundry_done
  - action: rest_command.todoist_create_task
    metadata: {}
    data:
      content: Remove laundry from washer
      description: "{{ laundry_done.data }}"
      due_string: today
      priority: 4
      section_id: YOUR_SECTION_ID # Take this from the browser if visiting the section in Todoist. Leave it out and task goes to inbox. You can use a project id, but set it up in the payload in configuration.yaml!
    response_variable: laundry_task
  - action: notify.mobile_app_pixel_9a # This is my phone. YMMV.
    metadata: {}
    data:
      message: "{{ laundry_done.data }}"
      title: Laundry is done!
      data:
        actions:
          - action: COMPLETE_TASK_{{ laundry_task['content']['id'] }} # This looks overcomplicated but was the only way I could get the task ID forwarded to a subsequent automation
            title: I did it!
mode: single
```
Again, there is much to tweak here.

## Completing the task
The previous automation labels the action in the notification as COMPLETE_TASK_(SOME_ID). This is needed to tell Todoist to remove the task with that particular ID. This is done in a separate automation:

```yaml
alias: "Close Laundry Task"
triggers:
  - event_type: mobile_app_notification_action
    trigger: event
conditions:
  - condition: template
    value_template: "{{ trigger.event.data.action.startswith('COMPLETE_TASK_') }}"
actions:
  - data:
      task_id: "{{ trigger.event.data.action.split('_')[-1] }}"
    action: rest_command.todoist_close_task
mode: parallel
```
